# Бэклог: что упрощено и надо доделать

## Срочная замена: что осталось (11.1-06)

Адресные предложения работают: `urgent_offer`, «принять / отказаться» в приложении, при принятии — назначение
с повторной проверкой ограничений, «смену получает первый» (блокировка строки заявки), остальным — «Смена уже занята»,
менеджеру — уведомление. Осталось:

- Push и SMS (сейчас только уведомления в приложении).
- Срок действия предложения и расширение круга кандидатов, если никто не принял.
- Живое обновление статуса на панели back-office без опроса.
- Имитация согласий в профиле `demo` (одно каждые 3 секунды) оставлена для презентационного стенда; убрать для пилота.

## Заявки клиентов: требования как жёсткие ограничения (12.1-07)

**Сейчас.** Требования из заявки (компетенции, «опыт на этом объекте») показываются в карточке заявки,
но при назначении в график не проверяются.

**Надо сделать:** при назначении в смену, на которую есть принятая заявка с требованиями, проверять их
как жёсткие ограничения (9.1) и фильтровать кандидатов. Заявки для этого стоит перенести в модуль
workforce (сейчас operations), чтобы правила назначения видели их без обратной зависимости модулей.

## Споры по табелю: что осталось (12.2)

- Сторона клиента: оспаривание и повторное подтверждение в портале (`/api/v1/portal/timesheets/{id}/disputes`,
  `/confirm`), вложения до 5 файлов.
- Напоминания обеим сторонам раз в 2 рабочих дня по открытым спорам (фоновая задача на `TenantScan`).
- Алерт менеджеру при новом споре.
- Счёт без оспоренных строк по настройке контракта (13.1).

## Портал клиента: что осталось (12)

- Вход через отдельный клиент Keycloak с 2FA; управление пользователями клиента (CLIENT_ADMIN).
- E-mail клиенту: «заявка отправлена», напоминание за 24 часа до срока подтверждения (12.2-03).
- Вложения к спору: до 5 файлов по 10 МБ (12.2-13).
- Пока табель «оспорен», неоспоренные строки по истечении срока должны приниматься автоматически (сейчас автопринятие только у табелей «ждёт подтверждения»).
- Разделы «Отчёты», «Документы», «Сообщения» — заглушки.

## Мобильное приложение и киоск: что осталось (14)

- Нативные сборки (Expo dev client / EAS) и проверка на устройствах iOS и Android; сейчас проверяется web-сборка.
- Вход по телефону и SMS через Keycloak (в демо — выбор персонажа); привязка устройства.
- Офлайн на WatermelonDB с синхронизацией (сейчас — очередь отметок в памяти устройства); у киоска — локальный кеш
  хешей PIN и карт, чтобы опознавать без сети (сейчас без сети уходит только уже начатая отметка).
- Фото отметки: снимается, но на сервер пока не загружается (только признак «фото было»); загрузка multipart
  в объектное хранилище со сроком хранения (7.4).
- Распознавание лица и проверка живости на сервере (ML, раздел 16), хранение и удаление шаблона по отзыву согласия;
  на киоске режим лица выключен.
- Часы из отметок в табель (9.2): сейчас табель строится из назначений; ручные отметки «на согласовании» должны
  попадать как неподтверждённые, отклонённые офлайн-отметки — в «Проблемы с отметкой» со статусом.
- Старший смены: «Закрыть смену» с проверкой отметок окончания, история выработки, журнал звонков, чат.
- Менеджер: решения по отпускам, обмену сменами, призам и баллам (нужны модули HR и мотивации), бонус срочной смены
  в баллах (раздел 15), шаблоны рассылки на 4 языках из раздела 6.
- Киоск: регистрация по QR из карточки объекта (10.2), MDM / Android Enterprise, сервисный код на устройство
  (в демо общий 2468), журнал нераспознанных попыток, стандарт карт СКУД (вопрос 19).
- QR-коды точек объекта: выпуск и печать из карточки объекта (сейчас в демо одна точка «вход 1»).
- Вкладка «Бонусы» — с модулем мотивации (раздел 15); загрузка документов работником; смена счёта через HR.
