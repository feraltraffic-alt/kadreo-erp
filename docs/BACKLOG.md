# Бэклог: что упрощено и надо доделать

## Срочная замена: настоящие согласия работников (11.1-06)

**Сейчас.** `POST /api/v1/urgent-requests` считает подходящих работников и записывает, скольким предложена смена
(`offered_to`), но самих предложений никто не получает. В профиле `demo` согласия имитируются:
`GET /api/v1/urgent-requests/{id}` добавляет одно согласие каждые 3 секунды
(`kadreo.demo.simulate-urgent-acceptance`, `OperationsService.urgentStatus`). В остальных профилях счётчик стоит на 0.

**Надо сделать** (вместе с мобильным приложением работника):

- Хранить адресные предложения: таблица `urgent_offer` (заявка, работник, статус «отправлено / принято / отклонено / истекло», время).
- Рассылать push и SMS выбранным работникам (до четырёх на место), с повторной проверкой ограничений перед отправкой.
- Эндпоинты приложения работника: список предложений, «принять», «отказаться».
- При принятии: в одной транзакции создать назначение (`assignment`, с `replaces_id` для замены неявки), увеличить `accepted`,
  повторно проверить жёсткие ограничения; когда мест не осталось — закрыть остальные предложения.
- Конкуренция: два работника принимают последнее место одновременно — побеждает первый, второй получает «место занято».
- Срок действия предложения и расширение круга кандидатов, если никто не принял.
- Уведомить менеджера о закрытии заявки; живое обновление статуса на панели.
- Убрать имитацию из демо-профиля, когда появится приложение (или оставить только для презентационного стенда).

## Заявки клиентов: требования как жёсткие ограничения (12.1-07)

**Сейчас.** Требования из заявки (компетенции, «опыт на этом объекте») показываются в карточке заявки,
но при назначении в график не проверяются.

**Надо сделать:** при назначении в смену, на которую есть принятая заявка с требованиями, проверять их
как жёсткие ограничения (9.1) и фильтровать кандидатов. Заявки для этого стоит перенести в модуль
workforce (сейчас operations), чтобы правила назначения видели их без обратной зависимости модулей.

## Споры по табелю: что осталось (12.2)

- Сторона клиента: оспаривание и повторное подтверждение в портале (`/api/v1/portal/timesheets/{id}/disputes`,
  `/confirm`), вложения до 5 файлов.
- Напоминания обеим сторонам раз в 2 рабочих дня по открытым спорам (фоновая задача на `TenantScan`).
- Алерт менеджеру при новом споре.
- Счёт без оспоренных строк по настройке контракта (13.1).

## Портал клиента: что осталось (12)

- Вход через отдельный клиент Keycloak с 2FA; управление пользователями клиента (CLIENT_ADMIN).
- E-mail клиенту: «заявка отправлена», напоминание за 24 часа до срока подтверждения (12.2-03).
- Вложения к спору: до 5 файлов по 10 МБ (12.2-13).
- Пока табель «оспорен», неоспоренные строки по истечении срока должны приниматься автоматически (сейчас автопринятие только у табелей «ждёт подтверждения»).
- Разделы «Отчёты», «Документы», «Сообщения» — заглушки.
