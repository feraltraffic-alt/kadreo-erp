# Kadreo ERP

Операционная платформа для аутсорсинга персонала на объектах клиентов (Польша, Германия): смены, учёт времени, табели, клиентский портал, биллинг с KSeF, расчёт зарплат по польскому праву, HR-compliance, мотивация и аналитика.

Название продукта — настройка брендинга тенанта (ТЗ 0.2): в коде оно не встречается, только в демо-данных.

## Этапы

1. Аудит экранов: что из ТЗ не покрыто макетами — готово.
2. Кликабельный фронт на демо-данных — итерация 1 готова (оперативная панель, смены, табели).
3. **Бэкенд** (Java 21, Spring Boot, Spring Modulith, PostgreSQL + PostGIS, Keycloak) — первый срез готов: ядро и API трёх экранов, фронт подключён.
4. Мобильное приложение и киоск (React Native + Expo) — первый срез готов: работник, старший смены, менеджер, киоск.

## Структура

```
apps/backoffice     web back-office (React 19, Vite, Tailwind, TanStack Query, MapLibre)
apps/portal         портал клиента (раздел 12 ТЗ): отдельное приложение на тех же пакетах
apps/mobile         мобильное приложение и киоск (раздел 14): Expo / React Native, iOS, Android и web-сборка
packages/ui         дизайн-система по разделу 8 ТЗ: токены, компоненты
packages/i18n       ICU MessageFormat, 4 языка (PL, UK, RU, EN), {productName}
packages/domain     доменные типы, контракт API, правила назначения и скоринг, демо-данные
backend             Spring Boot modular monolith: platform, organization, workforce, timetracking, operations, portal, mobile, demo
infra               init-скрипт БД, конфиг nginx
docs/BACKLOG.md     что упрощено и надо доделать
e2e                 сквозной сценарий в браузере против поднятого стенда
```

Экраны работают через интерфейс `Api` (`packages/domain/src/api.ts`). Его реализуют in-memory демо
(`createMockApi`) и HTTP-клиент к бэкенду (`createHttpApi`). Какой использовать, решает переменная
`VITE_API_URL`: не задана — демо в браузере; `/` — тот же адрес (nginx проксирует `/api`); полный URL — внешний бэкенд.

## Бэкенд

- Модули Spring Modulith, границы проверяются тестом. Данные тенантов разделены Row-Level Security в PostgreSQL:
  приложение ходит под ролью без владения таблицами, тенант берётся только из токена.
- Права проверяются на сервере по коду (`shift.schedule.edit`, …); 403 возвращает недостающее право.
- Профиль `demo`: фиксированные часы, тот же набор данных, что у фронтового демо (`packages/domain/scripts/export-seed.ts`
  → `backend/src/main/resources/demo/seed.json.gz`), вход через `POST /api/v1/dev/token`. Профиль `prod`: Keycloak.
- Документация API: `/swagger-ui.html`.
- Тесты: интеграционные на настоящем PostgreSQL + PostGIS (Testcontainers) сверяют цифры API с фронтовым демо.

## Стенд в Docker

```bash
docker compose up --build    # http://localhost:8081 — back-office, http://localhost:8082 — портал клиента,
                             # http://localhost:8083 — мобильное приложение и киоск (web-сборка), http://localhost:8080 — API
```

CI (GitHub Actions) собирает и тестирует бэкенд и фронт, поднимает этот стенд и проходит в браузере
оперативную панель, график смен, корректировку табеля, заявки, споры и поиск, а в портале — заявку
от клиента до принятия и табель от спора до подтверждения, а в мобильном приложении — перерыв и
принятие срочной смены работником, ручную отметку и запрос замены старшим, решение и замену менеджером,
отметку по PIN на киоске.

## Запуск фронта без бэкенда

```bash
pnpm install
pnpm --filter @kadreo/backoffice dev          # http://localhost:5173
pnpm --filter @kadreo/backoffice build        # обычная сборка в dist/
pnpm --filter @kadreo/backoffice build:demo   # один самодостаточный HTML в dist-demo/
pnpm typecheck
```

## Портал клиента (срез 1)

- Пользователь клиента видит только своего клиента: объекты, заявки и часы к выставлению; зарплатные данные и

- Обзор: люди на сменах сейчас, заявки, табели на подтверждение, показатели за неделю против целей контракта.

## Мобильное приложение и киоск (срез 1)

Одно приложение на Expo (React Native), вкладки по роли. Без `EXPO_PUBLIC_API_URL` работает на демо-данных в памяти,
с ним — против бэкенда; в демо вход выбором персонажа (в рабочей версии — телефон и код из SMS).

```bash
pnpm --filter @kadreo/mobile web              # http://localhost:8083, ?as=worker|leader|manager|kiosk
pnpm --filter @kadreo/mobile start            # dev-сервер Expo для телефона
```

- Работник (14.1, 14.5, макет 03): смена сегодня, геопозиция раз в 30 с без слежения, главная кнопка «Начать смену» →
  «Перерыв / Завершить» → «Вернуться к работе», фото с фронтальной камеры, QR точки объекта, «Проблема с отметкой»
  и «Опаздываю», ближайшие смены и срочные предложения с «Принять», график, документы, профиль (язык, согласие на
  биометрию с отзывом, PIN и QR для киоска). Без сети отметка сохраняется на телефоне и уходит сама.
- Сервер проверяет: смену работника, часы телефона (±5 мин; офлайн — до 72 ч), порядок отметок, окно начала,
  геозону объекта (запрет или «с пометкой» с комментарием), подпись QR; повтор с тем же ключом возвращает ту же отметку.
- Старший смены (14.2, макет 29): счётчики «по плану / на месте / опаздывают / не пришли», «Требуют внимания»,
  звонок, запрос замены, ответ работнику, ручная отметка на согласование (себя — нельзя), выработка смены.
- Менеджер (14.3, макет 30): укомплектованность, объекты с проблемами, «Найти замену» по скорингу (смену получает
  первый принявший), смена объекта глазами старшего, «Ждут моего решения» с ✓ (5 секунд на отмену) и ✕ с причиной
  (правило четырёх глаз), срочная смена с бонусом, рассылка бригаде.
- Киоск (14.4, макет 31): табельный номер + PIN (5 ошибок — блокировка на 15 минут), карта через считыватель,
  QR из приложения (подпись сервера, 30 секунд), выбор действия, результат на 5 секунд (принято / опоздание /
  без смены — на согласование), последние отметки, языки, состояние связи и очередь.
