# Kadreo ERP

Операционная платформа для аутсорсинга персонала на объектах клиентов (Польша, Германия): смены, учёт времени, табели, клиентский портал, биллинг с KSeF, расчёт зарплат по польскому праву, HR-compliance, мотивация и аналитика.

Название продукта — настройка брендинга тенанта (ТЗ 0.2): в коде оно не встречается, только в демо-данных.

## Этапы

1. Аудит экранов: что из ТЗ не покрыто макетами — готово.
2. Кликабельный фронт на демо-данных — итерация 1 готова (оперативная панель, смены, табели).
3. **Бэкенд** (Java 21, Spring Boot, Spring Modulith, PostgreSQL + PostGIS, Keycloak) — первый срез готов: ядро и API трёх экранов, фронт подключён.
4. Мобильное приложение и киоск (React Native + Expo).

## Структура

```
apps/backoffice     web back-office (React 19, Vite, Tailwind, TanStack Query, MapLibre)
packages/ui         дизайн-система по разделу 8 ТЗ: токены, компоненты
packages/i18n       ICU MessageFormat, 4 языка (PL, UK, RU, EN), {productName}
packages/domain     доменные типы, контракт API, правила назначения и скоринг, демо-данные
backend             Spring Boot modular monolith: platform, organization, workforce, timetracking, operations, demo
infra               init-скрипт БД, конфиг nginx
docs/BACKLOG.md     что упрощено и надо доделать
e2e                 сквозной сценарий в браузере против поднятого стенда
```

Экраны работают через интерфейс `Api` (`packages/domain/src/api.ts`). Его реализуют in-memory демо
(`createMockApi`) и HTTP-клиент к бэкенду (`createHttpApi`). Какой использовать, решает переменная
`VITE_API_URL`: не задана — демо в браузере; `/` — тот же адрес (nginx проксирует `/api`); полный URL — внешний бэкенд.

## Бэкенд

- Модули Spring Modulith, границы проверяются тестом. Данные тенантов разделены Row-Level Security в PostgreSQL:
  приложение ходит под ролью без владения таблицами, тенант берётся только из токена.
- Права проверяются на сервере по коду (`shift.schedule.edit`, …); 403 возвращает недостающее право.
- Профиль `demo`: фиксированные часы, тот же набор данных, что у фронтового демо (`packages/domain/scripts/export-seed.ts`
  → `backend/src/main/resources/demo/seed.json.gz`), вход через `POST /api/v1/dev/token`. Профиль `prod`: Keycloak.
- Документация API: `/swagger-ui.html`.
- Тесты: интеграционные на настоящем PostgreSQL + PostGIS (Testcontainers) сверяют цифры API с фронтовым демо.

## Стенд в Docker

```bash
docker compose up --build    # http://localhost:8081 — back-office, http://localhost:8080 — API
```

CI (GitHub Actions) собирает и тестирует бэкенд и фронт, поднимает этот стенд и проходит в браузере
оперативную панель, график смен, корректировку табеля и поиск.

## Запуск фронта без бэкенда

```bash
pnpm install
pnpm --filter @kadreo/backoffice dev          # http://localhost:5173
pnpm --filter @kadreo/backoffice build        # обычная сборка в dist/
pnpm --filter @kadreo/backoffice build:demo   # один самодостаточный HTML в dist-demo/
pnpm typecheck
```

## Готово в итерации 1

- Каркас back-office: меню с правами и счётчиками, свёртывание до 72 px, глобальный поиск Ctrl K, уведомления, переключение роли и языка, страница 403, режим узкого экрана (8.3–8.5).
- Оперативная панель (11.1): KPI с детализацией, карта объектов со статусами и кластерами, алерты с «Подобрать замену» и «Взять в работу», срочная замена, таблица объектов.
- Планирование смен (9.1): список проектов, сетка недели, рекомендации кандидатов с причинами, жёсткие ограничения (документы, отдых 11 ч, лимит часов, доступность), назначение кнопкой и перетаскиванием, меню ячейки, автораспределение с предпросмотром, публикация.
- Табель (9.2): список табелей, этапы подтверждения, фильтры, панель корректировки с отметками и доказательствами, обязательная причина, история «было / стало», выгрузка XLSX, отправка клиенту.
